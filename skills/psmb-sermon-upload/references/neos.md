# Neos sermon field reference

## Calendar links

- A plain `DD/MM` in **Дата** is old style (Julian). The application subtracts 13 days from the civil calendar date for fixed-date matching in current years. For example, Christmas on civil January 7 is `25/12`. Verify the intended feast and its calendar convention before encoding it.
- Pascha-relative keys use `week;weekday`. Pascha is `1;0` and Wednesday of Bright Week is `1;3`. Weekdays run Sunday `0` through Saturday `6`. For other liturgical weeks, check the app, an existing sermon for that feast, or the site matcher. Its week numbering resets before the next Pascha.
- Fixed-date keys can also specify a weekday relative to a feast. The matcher uses `-` before, `+` after, and `~` nearest. `25/12~6` means the Saturday nearest old-style December 25. `25/12-0#1` means one week before the Sunday preceding that date. `25/12-w` uses the date itself if it falls Monday through Friday, or the preceding Friday on a weekend. In this syntax `0` means Sunday. Check the matcher or a known-good sermon if the inspector help's prose conflicts with the numeric code.
- For **Отрывок**, use a single exact label from the [calendar app](https://molitva.app/)'s **Литургия** readings. Open a known civil date with `https://molitva.app/#/date/YYYY-MM-DD`. On [1 November 2026](https://molitva.app/#/date/2026-11-01), Galatians 6:11–18 is `Гал., 215 зач., VI, 11-18.` The same зачало can occur with different verse limits. Do not guess from its number or join multiple labels into one.
- Where the project checkouts are available, use `calendar-backend/Data/processed` to corroborate exact reading strings and `PsmbDistr/Packages/Sites/Sfi.Site/Classes/Sfi/Site/FlowQueryOperations/FilterByMagicDateOperation.php` to resolve key semantics. Use the calendar app to resolve discrepancies with local data.

## Editor and workspace controls

- The top **Create** box is for materials. Use **Create new** in the **Document Tree** for a sermon. The **Проповеди** row is labeled **Shortcut**. Open its chevron to show its children. Select a known sermon under it and insert **after** that child to preserve the parent. The title field in the creation dialog shares an ID with the inspector title field, so scope it to the dialog. If the expanded tree truncates the browser snapshot, inspect the needed controls in the DOM.
- The author and theme fields each have a **Type to search** input. Scope by the field label and wait for search results. A **Create new** choice may appear before results arrive. Select the verified item, distinguishing authors under `/tags/people/` and themes under `/themes/`. Use the author picker's **Create new** only for a confirmed missing author. The stand-alone **Автор** page type is a different node type.
- The preview iframe has inline editors for title, teaser and body. It can briefly retain the preceding page after selection changes. Wait for the inline title and the body editor's `data-__neos-editable-node-contextpath` to identify the new draft before editing. The body editor is `[data-__neos-property="text"][contenteditable="true"]`. Paste formatted content there, then blur to commit. When the preview tool supports same-origin DOM interaction, dispatch `ClipboardEvent('paste', {bubbles: true, cancelable: true, clipboardData})` with an HTML payload of escaped paragraphs on the focused editor using the iframe's `DataTransfer` and `ClipboardEvent` constructors. Preserve meaningful emphasis and links from the source. Verify after reopening because rendered text alone does not prove a save.
- Inspector **Apply** queues the fields for saving. Some operations take tens of seconds. **Publish to live** with a count indicates pending changes and is a live action. Use its separate dropdown chevron for **Review changes**, **Workspaces**, or the current-document **Discard**. A new sermon can produce multiple pending nodes for the page, collection, and text. The scoped discard dialog describes its count as changes “in this workspace,” so verify the selected page and check that the count and pending changes belong to the test before confirming. In a workspace that started clean, discarding that draft should return it to **Published - live** with the test title absent from the tree.
